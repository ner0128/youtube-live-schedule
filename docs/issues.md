## 작성 기준

### ID

- 이슈 번호는 I-두 자리(I-01, I-02). 지운 번호는 다시 쓰지 않음.
- GitHub Issue 번호는 Task·기능과 같이 매겨져 이슈끼리 번호가 연속되지 않음. GitHub 칸에 짝만 적음.

### 유형

| 값 | 뜻 |
|---|---|
| 버그 | 요구사항대로 동작하지 않음 |
| 개선 | 동작은 맞지만 더 낫게 할 수 있음. 받아들이면 명세서 보류·제안(P) 또는 기능(F)으로 옮김 |
| 검토 | 버그인지 정해진 동작인지 판단이 필요함. 결정되면 명세서 확인 필요(Q)로 옮기거나 버그로 바꿈 |
| 문서 | 동작은 맞지만 명세서 설명이 틀리거나 빠짐 |

### 분류

명세서 기능 요구사항(F)의 '구분' 값을 씀. 비기능(N) 이슈는 '비기능'으로 두고, 관련 요구사항에 해당 번호를 적음. 이슈가 여러 영역에 걸치면 증상이 보이는 영역을 복수로 기재함. (쉼표로 구분, 증상이 가장 크게 보이는 영역을 먼저)

| 값 | 명세서 항목 |
|---|---|
| 채널 관리 | F-01~F-03 |
| 일정 조회 | F-04~F-09 |
| 전체 화면 창 | F-10~F-13 |
| 오버레이 | F-20~F-27 |
| 트레이 | F-30 |
| 확인용 채널 | F-40~F-46 |
| 실행 | F-50~F-54 |
| 비기능 | N-01~N-08 |

### 심각도 (문제의 크기)

| 값 | 뜻 |
|---|---|
| 치명 | 크래시 혹은 의도치 않은 비가역적 손상 (채널 데이터, 설정 등) |
| 높음 | 주요 기능을 사용할 수 없음, 우회 불가 |
| 보통 | 불편하지만 우회 가능, 또는 특정 조건에서만 발생 |
| 낮음 | 화면 표시 문제, 기타 마이너 이슈 |

### 우선순위 (먼저 고칠 정도)

| 값 | 뜻 |
|---|---|
| 높음 | 다음 수정 때 반드시 수정. 자주 쓰는 흐름에서 자주 발생하고 우회 방법이 없음 |
| 보통 | 수정 계획에 넣음. 특정 조건에서만 발생하거나 우회할 수 있음 |
| 낮음 | 여유 있을 때 수정. 발생 빈도가 매우 낮거나 기능상의 문제가 없음 |

### 재현

항상 / 자주 / 가끔 / 한 번. '한 번'이면 Issue 댓글에 기재.

### 상태

GitHub Issue에서 관리함. 해결되면 Issue를 닫고(완료 / 계획 없음 / 중복), 진행 기록은 Issue 댓글에 남김.

### 버전 표기

버전 번호 도입 전이라 빌드 날짜로 적음 (예: 2026-11-06 빌드). 명세서 개요의 '기준: 2026-11-06 빌드'와 같음.

### 요구사항 명세서와 연결

- 버그가 확인되면 명세서의 해당 F·N 항목 상태를 '수정 필요'로, 비고에 I 번호.
- 해결되면 '구현됨'으로 되돌리고 변경 이력에 I 번호.
- 고치지 않기로 한 버그는 명세서 알려진 한계(L)로 남김.
